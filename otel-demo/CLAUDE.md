# otel-poc

Usage tracking and session replay for legacy web apps on an airgapped RKE2 cluster, with no
changes to the apps. Built on the connected side (this Mac), carried across as a tar, installed
with plain `helm package` + `helm install`. No install scripts on the high side, by request.
Java desktop apps (Swing on Java 6+, JavaFX) are covered by `ui-agent`, a dependency-free Java
agent that sends the same shapes to the same collector.

## Layout

- `bundle/src/poc.js`: the one browser script. esbuild bundles it (OTel web SDK + OpenObserve RUM
  and logs, recorder included) into `bundle/dist/poc.js`, target `firefox115,chrome109`.
  High-side users run Firefox ESR 140.
- `proxy/Containerfile`: nginx `1.30.5-alpine` with `poc.js` baked in at `/usr/share/nginx/poc/`.
  The stand-in app reuses this image.
- `chart/`: the Helm chart. OpenObserve, the Collector, the proxy, an optional stand-in app, and
  one ingress per app plus one for OpenObserve.
- `build.sh`: builds everything for linux/amd64 into `out/` (images tar, `chart/`, `README.md`,
  `SHA256SUMS`). `otel-poc-transfer.tar` is just `out/` tarred up for the transfer.
- `README.md`: high-side install steps. Keep it short; it ships in the bundle.
- `chart/files/dashboard.json`: the "Web app usage" OpenObserve dashboard. Nothing in the chart
  reads it; import it in the OpenObserve UI after each restart. The hidden `o2_url` variable is
  the address browsers use for OpenObserve (the replay links need it) and defaults to
  `http://openobserve.poc.local`. The UI import refuses an empty `dashboardId`; OpenObserve assigns
  its own ID anyway, so the file's `web-app-usage` is just a placeholder.
- `chart/files/feature_catalog.csv`: one feature list for all apps (web and Java), loaded by hand
  as the enrichment table `feature_catalog`. `chart/files/dashboards/`: "Usage summary", "Feature
  inventory", "Collection coverage", "Java app health". Generated by `tools/make_dashboards.py`;
  edit the SQL there. `--web-only` leaves the Java view stream out of the page panels.
- `tools/check_catalog.py`: connected side only. Fails if an observed page or control matches more
  than one catalog row; lists pages matching none. Has an assert self-test.
- `ui-agent/`: the Java agent. `src/poc/uiagent/*.java`, no dependencies, compiled `-source 1.6`
  against the Zulu 6 `rt.jar` inside `Containerfile` so one jar runs on Java 6 through 21.
  `build.sh` writes `dist/ui-agent.jar` (~70 KB). `README.md` is the install card that ships in
  `out/ui-agent/`.
- `kind/`: Redpanda + Console v3.9.0 and Headlamp v0.44.0 for testing, plus `values.yaml` pointing
  the proxy at them. Not shipped. `docs/demo-walkthrough.md`: demo order and high-side click list.
  `docs/java-ui-findings.md`: what the Java agent matrix showed and the attach-mode ranking.

## How data flows

nginx sits in front of each app (one `server` block per `apps[]` entry, matched by hostname) and
`sub_filter`s a `<script defer src="/__poc/poc.js" data-app data-version data-env data-org
data-privacy>` tag before `</head>`. Everything the browser sends stays on the app's own origin,
so there is no CORS and a CSP only needs `'self'`:

- `/__poc/otlp/` → Collector `:4318` (OTLP HTTP) → OpenObserve traces stream `default`
- `/__poc/o2/rum/` → OpenObserve `/rum/` (RUM events to `_rumdata`, replay to `_sessionreplay`)
- `/__poc/o2/token` → OpenObserve `/api/<org>/rumtoken`, GET only, nginx adds Basic auth
- nginx access log → syslog UDP `:5140` → Collector `syslog/nginx` receiver → logs stream `nginx_access`

Java desktop apps run `ui-agent` in the app's JVM. It posts hand-built OTLP/JSON over
`HttpURLConnection` to `http://<proxy>:4318/v1/{traces,logs,metrics}`; the proxy's `otlpPort`
server block (`access_log off`, `$poc_app = _otlp`) passes `/v1/` to the collector `:4318`.

- traces → stream `default`, same columns as browser interaction spans plus `ui_toolkit`
- logs with a `type` attribute (`view`, `error`) → `filter/views` → stream `ui_views`, RUM column names
- logs without `type` (app log lines, stdout/stderr, `freeze`) → `filter/app_logs` → stream `java_logs`
- metrics → one OpenObserve metrics stream per metric name (`jvm_memory_used`, `ui_event_thread_freezes`, ...)
- `filter/self_export` drops client spans whose `url.full` ends in `/v1/traces|logs|metrics`, so an
  OpenTelemetry Java agent running next to ui-agent does not trace ui-agent's own exports.

OpenObserve flattens span attributes: query `target_text`, `page_path`, `rum_session_id`, not
`attributes_*`. `rum_session_id` on spans equals `session_id` in the replay streams.

Field names (checked on v1.0.4 in kind; org is `data-org`, `default`):

- `data-app` is `service_name` on spans, `service` (and `application_id`) on RUM rows, `app` in
  `nginx_access`. `data-version` is `service_service_version` / `version`.
- Spans: `event_type` (`click`/`change`/`submit`, empty on load and fetch spans), `page_path`
  (pathname only, no query or hash), `target_text`, `target_element`, `target_xpath`, `url_full`.
- RUM (`_rumdata`): `type` (`view`, `action`, `error`, `resource`, `long_task`), `view_id`,
  `session_id`, `view_url` (full URL; there is no path field), `view_time_spent` (nanoseconds),
  `view_loading_type` (`initial_load` or `route_change`). Errors: `error_message`, `error_stack`,
  `error_source`. RUM action names are "Masked Element" under `privacy: mask`.
- `nginx_access`: `uri`, `args`, `status` (float), `method`, `upgrade`, `content_type`
  (`text/html...` marks a page load; 304s have none), `request_time`. `app` is `_probe` for the
  readiness probe and empty for the catch-all server.
- Java agent resource attributes flatten differently per stream type: on spans they are
  `service_name`, `service_deployment_environment_name`, `service_service_version`; on logs and
  metrics they are `service_name`, `deployment_environment_name`, `service_version`. `ui_views`
  rows also carry the RUM-style `service`, `application_id`, `version`, `env`, `session_id`.
  `page_path`/`view_url` are `/Window title/Tab title` or `/Owner title/Dialog title`, never a URL.
- `java_logs`: `kind` (`app_log`, `stdout`, `stderr`, `freeze`, `freeze_end`, `uncaught_exception`),
  `severity` (`ERROR`/`WARN`/`INFO`/`DEBUG`), `logger`, `thread`, `body`, `exception_stacktrace`.

## Decisions that look odd but are deliberate

- **RUM token fetched at runtime.** OpenObserve generates the org RUM token at startup and RUM
  ingest rejects anything else (Basic auth doesn't work there). Serving it from the proxy is what
  lets a single `helm install` work. The nginx config therefore holds credentials and is a
  **Secret**, not a ConfigMap.
- **Capture listener on `document`.** The user-interaction instrumentation only sees listeners
  added with `addEventListener`, so `onclick=` legacy pages produced no spans. `poc.js` adds a
  no-op capture listener for `click`, `change`, `submit` after registering instrumentations.
- **Nested spans dropped.** The instrumentation opens one span per listener, chained. We keep only
  the root (`if (span.parentSpanContext) return true`), so one interaction is one span.
- **Interaction spans flushed immediately.** On a click that navigates, the page-hide flush lost to
  the replay upload for the browser's shared keepalive budget. `onEnd` force-flushes any span with
  `event_type`.
- **Syslog instead of filelog** for access logs: no shared volumes or node log DaemonSet.
- **OpenObserve on emptyDir by default** (`persistence.enabled: false`): a restart drops collected
  data. Keeping it is `persistence.enabled` plus `persistence.storageClass` (Ceph on Env 1 and 2).
  Env 3 sets `persistence.local.enabled` and one local volume. The chart has no hostPath.
- **Config checksums** hash the rendered `*-config.yaml` templates, so template-only changes roll
  the pods. Hashing `.Values` alone missed them once.
- `poc.js` is served with `Cache-Control: no-cache`; stale cached copies hid a fix during testing.
- **Everything runs as uid/gid 1000** under the "restricted" security context (the high-side
  cluster requires it). Stock nginx can't write `/var/run` or `/var/cache/nginx` as that user, so
  both nginx configs put `pid` and all `*_temp_path`s in `/tmp`, and the stand-in listens on 8080
  with its own config at `/etc/standin/nginx.conf`. Root filesystems are read-only, so every pod
  mounts an emptyDir on `/tmp` (OpenObserve also mounts its data volume on `/data`). Test with
  `kubectl label ns otel-poc pod-security.kubernetes.io/enforce=restricted`.
- **`proxy.hostAliases`** exists because high-side app servers are bare metal boxes the cluster DNS
  doesn't know (for example `sysvue`), and nginx crash-loops on an unresolvable upstream. Upstreams
  are server-only URLs with no path; a path in `proxy_pass` rewrites every request and breaks SPAs.
- **Multus, not the ingress, is how high-side browsers reach the cluster.** `proxy.networkAttachments`
  and `openobserve.networkAttachments` (`enabled`, `networks` with `name`, `namespace`, and `ips`)
  carry the network. The chart refuses to render when enabled without an IP, and the proxy refuses
  when `replicas` is not 1. Separate per pod because each pins its own IP. Because a raw IP matches no
  `server_name`, `apps[].port` adds a per-app `listen` so `http://<proxy IP>:<port>/` works with no
  DNS. The first real app is `sonsym` at `https://sysvue:8443`, served under `/sysvue/`.
- **WebSockets pass through** (`proxy_http_version 1.1` plus `Upgrade`/`Connection` headers,
  1h read timeout). That alone was not enough for sysvue: the browser Origin is
  `http://<multus>:8081`, and an HTTPS app that checks Origin rejects it. For `https://`
  upstreams (or an explicit `apps[].origin`) the proxy rewrites Origin, strips Secure on
  cookies, hides HSTS, and rewrites redirects. `openobserve.url` bypasses a dead cluster
  Service when Multus stole the default route.
- **Icon-button clicks are credited to the button.** The click lands on the `<svg>`, and
  instrumentation-user-interaction only makes spans for `HTMLElement` targets, so Headlamp's Show
  Logs, Scale, Edit produced nothing. `poc.js` wraps the private `_createSpan` and walks up to the
  nearest HTML element; the package is pinned exactly (`0.66.0`) because of that.
- **`apps[].privacy`** overrides `openobserve.privacyLevel` per app. Headlamp uses `mask`.
- **The readiness probe is logged** as `app = "_probe"`: a heartbeat so Collection coverage can
  tell "proxy up, nobody used it" from "proxy down".
- **Every pod sets `priorityClassName: mission-specific`** (high-side requirement). In kind, create
  it first: `kubectl create priorityclass mission-specific --value=1000000`.
- **`ui-agent` has no dependencies and targets Java 6.** The real apps include Java 6 and 7 JVMs,
  and the OpenTelemetry Java SDK needs 8. So OTLP/JSON is written by hand (`Json`, `Exporter`)
  and posted with `HttpURLConnection`; no protobuf. Compiled with Zulu 8 `javac -source 1.6
  -target 1.6 -bootclasspath <Zulu 6 rt.jar>` so a newer API can't slip in. No lambdas, no
  diamond, no try-with-resources in `ui-agent/src`.
- **Swing: `AWTEventListener` plus listener injection, not bytecode weaving.** `COMPONENT_ADDED`
  events find every new control; the agent adds its own `ActionListener`/`ChangeListener` to
  buttons, menu items, combos, sliders, spinners, text fields (and the AWT equivalents). Clicks
  on tables, lists, trees, and custom components come from `MOUSE_CLICKED` on the deepest
  component. No instrumentation API beyond `premain`/`agentmain`, so it also works via attach.
- **`UserEventQueue` tells user actions from programmatic ones.** A pushed `EventQueue` subclass
  marks, per thread, whether the event being dispatched came from input (mouse, key, or a
  heavyweight AWT component's own `ActionEvent`). Listener callbacks outside that are
  `setSelected()` calls by the app and are not counted. `EventQueue.getCurrentEvent()` was
  wrong for menu items: by the time the action fires, the current event is the popup's hide.
- **JavaFX entirely by reflection and `java.lang.reflect.Proxy`.** The agent jar has no FX
  classes on its class path (and FX is a module on 9+), so `FxHook` polls for
  `javafx.stage.Window`, then adds scene event filters (`ACTION`, `MOUSE_CLICKED`,
  `MOUSE_RELEASED`) with proxied `EventHandler`s. `Window.getWindows()` on 9+,
  `com.sun.javafx.stage.StageHelper.getStages()` on 8.
- **Page = `/Window title/Selected tab`.** Swing and JavaFX apps have no URL; the window title and
  the first tab pane's selected tab are the closest thing users and catalog authors recognise.
  Dialogs are `/Owner title/Dialog title`. One active view at a time across both toolkits
  (`Views`), so a Swing dialog from a JavaFX app closes the FX view and opens its own.
- **Labels fall back to the preceding label.** Combos, sliders, spinners, and text fields have no
  text of their own; `label()` uses text → `labelFor` → tooltip → accessible name → component
  name/id → the `JLabel`/`Label` just before the control in the same parent (`precedingLabel`).
  Accessible name is never used for text components (it can be the typed value).
- **Freeze detection by pinging the event thread** every second with `invokeLater`/`runLater`;
  a ping outstanding longer than `freeze_ms` (500) logs the event thread's stack once, and the
  completion logs `freeze_end`. Cheap, works on Java 6, no JFR.
- **stdout/stderr tee holds a line for 300 ms** so a printed stack trace becomes one `java_logs`
  row with the frames in `exception_stacktrace`, not one row per frame (814 frame rows in the
  first matrix run). Lines that log4j/JUL console appenders already logged are skipped by pattern.
- **Log records routed by an attribute, not a separate port.** ui-agent sends views and errors
  with a `type` attribute and RUM column names so they can sit next to `_rumdata`; everything
  else lacks `type`. Two `filter` processors split them in the collector into `ui_views` and
  `java_logs`. One OTLP endpoint for everything keeps the install card to one URL.
- **Page panels `UNION ALL` `_rumdata` and `ui_views`.** Verified: the catalog `LEFT JOIN` onto
  the union keeps the catalog half (the earlier failure was catalog-in-union, which still
  holds). The error panel is not unioned because a stream that lacks a column fails the whole
  query, and `ui_views` has no `error_*` columns until the first exception.

## Version pins

Proxy `0.1.1`, OpenObserve `v1.0.4`, `otelcol-contrib` `0.161.0`, nginx `1.30.5-alpine`, chart
`0.2.0`, `ui-agent` `0.1.0` (`ui-agent/MANIFEST.MF` and `Agent.VERSION`). Bumping an image means
editing `build.sh`, that image's `tag` in `chart/values.yaml`, the comment at the top of
`chart/values.yaml`, and the push loop in `README.md`. Chart changes bump `version` in
`Chart.yaml`. Rebuild the proxy image (and bump its tag) whenever `poc.js` changes.

The collector's `otlp_http` exporter is the 0.161.0 name; older contribs call it `otlphttp`.
The agent was checked beside OpenTelemetry Java agent `2.33.1`.

```bash
kind create cluster --name otel-poc
(cd bundle && npm run build)
R=registry.local:5000/otel-poc
docker build -t $R/proxy:0.1.1 -f proxy/Containerfile .
docker pull public.ecr.aws/zinclabs/openobserve:v1.0.4 && docker tag public.ecr.aws/zinclabs/openobserve:v1.0.4 $R/openobserve:v1.0.4
docker pull otel/opentelemetry-collector-contrib:0.161.0 && docker tag otel/opentelemetry-collector-contrib:0.161.0 $R/otelcol-contrib:0.161.0
kind load docker-image --name otel-poc $R/proxy:0.1.1 $R/openobserve:v1.0.4 $R/otelcol-contrib:0.161.0
printf 'global:\n  imageRegistry: registry.local:5000\napps:\n  - {name: standin, version: "1.0", host: standin.localhost, upstream: "http://otel-poc-standin:8080"}\n' > /tmp/kind-values.yaml
helm package chart -d /tmp && helm install otel-poc /tmp/otel-poc-0.2.0.tgz -n otel-poc --create-namespace -f /tmp/kind-values.yaml --wait
kubectl -n otel-poc port-forward svc/otel-poc-proxy 8080:80 &
kubectl -n otel-poc port-forward svc/otel-poc-openobserve 5080:5080 &
```

For the usage dashboards, use the demo apps instead of the stand-in:
`kind load docker-image` the three images in `kind/demo-apps.yaml`, `kubectl apply -f
kind/demo-apps.yaml`, install with `-f kind/values.yaml`, and log into Headlamp with
`kubectl -n demo create token headlamp`. Browse `http://console.localhost:8080` and
`http://headlamp.localhost:8080`.

Browse `http://standin.localhost:8080` (Chrome and Firefox resolve `*.localhost`) and
`http://localhost:5080` (`admin@poc.local` / `ChangeMe-PoC-1`). After a rebuild with the same
tag, `kind load` again and `kubectl rollout restart deploy/otel-poc-proxy`; port-forwards die on
every proxy rollout. Tear down with `kind delete cluster --name otel-poc`.

The catalog and dashboards can be loaded by API instead of the UI:
`curl -u admin@poc.local:ChangeMe-PoC-1 -F file=@chart/files/feature_catalog.csv -X POST
"http://localhost:5080/api/default/enrichment_tables/feature_catalog?append=false"` and, per
file, `curl -u ... -X POST "http://localhost:5080/api/default/dashboards?folder=default"
-H 'Content-Type: application/json' --data-binary @chart/files/dashboards/<name>.json`.
`python3 tools/make_dashboards.py --sql` prints every panel's SQL, and running each one against
`/api/default/_search?type=<stream_type>` with `$app` replaced by `'_o2_all_'` is the quickest
panel check.

A Java desktop agent on this Mac reaches that collector with
`kubectl -n otel-poc port-forward --address 0.0.0.0 svc/otel-poc-proxy 4318:4318`.

## Usage dashboards

OpenObserve SQL quirks found in v1.0.4 (all verified against the API and in dashboard panels):

- A join to the catalog needs an equality in `ON` (`v.service = c.app`). With only `LIKE` or
  `regexp_like` in `ON`, the join silently returns nothing.
- Write the catalog as `enrich.feature_catalog`. Enrichment rows aren't filtered by time range.
- **One stream type per query.** With the catalog first, only the query's own stream type is read
  (a `"traces"."default"` join from a logs query scans 0 rows). A cross-type join next to the
  catalog also dropped a span a direct query returned. Same-type joins match direct counts. So
  pages (RUM, logs) and controls (spans, traces) are separate panels.
- `UNION ALL` of the catalog with usage rows lost the catalog half; `LEFT JOIN` from the catalog
  works. `UNION ALL` of two same-type streams (`_rumdata` and `ui_views`) inside the usage
  subquery works and the catalog `LEFT JOIN` onto it keeps every catalog row.
- A query fails outright (HTTP 400, no partial result) if a stream in it does not exist
  (`Search stream not found`) or a column is missing from one stream (`unknown field`). Streams
  and columns appear on first ingest, so new sites hit this; hence `--web-only`.
- Metrics panels: `stream_type: metrics`, one stream per metric name, columns `value`,
  `_timestamp`, flattened resource and data point attributes (`jvm_memory_type`). `histogram()`
  and `max(value)` work as on logs.
- Don't alias a column to a name the stream already has (`source` in `_rumdata`).
- A table timestamp column that starts with nulls shows raw microseconds; format it with
  `to_char(to_timestamp_micros(x), ...)` (UTC).
- The `$app` dropdown is a `query_values` variable over one stream. The usage dashboards use
  `nginx_access.app`, so Java apps only match when the dropdown is on All (`_o2_all_`); the Java
  app health dashboard overrides it to `java_logs.service_name` (`dashboard(..., app_source=)`).

Counting: sessions are `count(DISTINCT session_id)` (any view); views are distinct `view_id` that
stayed open at least 1 s, because Console redirects (`/topics` to `/topics/`) add sub-second views.
Interactions are spans with `event_type IN ('click', 'change', 'submit')`.

Catalog rules (`feature_catalog.csv`, `check_catalog.py` enforces most):

- Columns `feature_id, app, feature_name, kind, path_pattern, element_label, writes, notes`. No
  commas or quotes in values.
- `path_pattern` is an anchored regex (`^...$`) matched with `regexp_like` against the normalized
  path: origin, query string, and trailing slash dropped, hash kept (`regexp_replace` in
  `tools/make_dashboards.py`, `PATH`). Spans have no hash, so control patterns never include one.
- `page` rows count RUM views; `control` rows count spans with `target_text = element_label` on a
  matching page. Patterns must not overlap for the same app and kind.
- Console: topic tabs are hashes (`#partitions`, `#consumers`, `#configuration`, `#topicacl`;
  Messages is the default with no hash). Headlamp: paths are `/c/<cluster>/...`; pod and
  deployment details open in a side panel without changing the URL, so they are controls
  (Show Logs, Scale) on the list page, not pages.
- Java apps: pages are `^/Window title/Tab$`, dialogs `^/Owner title/Dialog title$` (or
  `^/Dialog title$` with no owner, like a JavaFX `Alert`). Menu items and toolbar buttons fire on
  whichever tab is showing, so their pattern is `^/Window title/[^/]+$`. Tab headers are
  recorded as clicks but excluded from the uncataloged-controls panel (`JTabbedPane`, `TabPane`)
  because the tab is already a page. Labels: the `UI_AGENT_DEBUG` output shows the exact
  `[Label]` to use; icon buttons without a tooltip have none and cannot be cataloged.

## Known gaps

- Clicking a row records its visible text, so Headlamp resource names (pod, Secret names) land in
  `target_text`. Values aren't captured, but keep Secrets out of demo traffic.
- High-side Console and Headlamp versions aren't confirmed; kind uses Console v3.9.0 and Headlamp
  v0.44.0. Other versions may change routes, so rerun `check_catalog.py` after real traffic.
- RUM's own click `action` events don't show up in `_rumdata`. The OTel spans are the usage record.
- RUM sends a view event again each time the view updates. Count `distinct view_id`, and take
  `max(view_time_spent)` per view for time on page.
- No alerts. Alert destinations on localhost or private addresses are refused unless
  `ZO_SSRF_ALLOW_LOOPBACK` or `ZO_SKIP_SSRF_CHECKS` is set, and real-time alerts skip rows that
  pass through a pipeline.
- Release name must stay `otel-poc` unless the stand-in's `upstream` in `values.yaml` changes.
- High-side snags (CIS Pod Security, upstream DNS at nginx start, the
  `Host` header) are listed in `README.md`.
- Java agent: no replay for desktop sessions; attach mode (C) misses everything before the
  attach; unlabelled icon buttons and custom panels are clicks with an empty `target_text`;
  the OTLP port on the proxy is plain HTTP with no auth, same as the browser path through
  `/__poc/otlp/`. When the OpenTelemetry Java agent runs alongside, its JUL log export lands
  in `java_logs` without a `kind` (duplicates of the app's own lines). The full list is in
  `docs/java-ui-findings.md`.
